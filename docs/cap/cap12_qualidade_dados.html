12  Valores ausentes e qualidade dos dados

Verificando antes de analisar

Author

Alexandre Nicolella

Published

September 1, 2026

No capítulo anterior, carregamos a base wage1, selecionamos um núcleo de variáveis e importamos os mesmos dados em CSV, Excel e RDS. Conseguir abrir um arquivo, entretanto, não significa que a base esteja pronta para análise.

Antes de calcular médias, construir gráficos ou estimar modelos, precisamos perguntar se os dados representam adequadamente aquilo que imaginamos. Valores ausentes, códigos inválidos, linhas duplicadas e relações incoerentes podem alterar os resultados ou revelar que ainda não compreendemos a base.

NoteObjetivos do capítulo

Ao final deste capítulo, você deverá ser capaz de:

  • distinguir ausência de informação e valor zero;
  • localizar e contar valores NA;
  • utilizar na.rm conscientemente;
  • identificar valores fora de regras plausíveis;
  • localizar linhas duplicadas;
  • verificar coerência entre variáveis relacionadas;
  • evitar correções automáticas sem justificativa;
  • registrar as decisões tomadas durante a limpeza;
  • formular verificações que possam ser executadas novamente.

12.1 Qualidade depende do problema

Uma base não é simplesmente “boa” ou “ruim”. Sua qualidade precisa ser avaliada em relação à pergunta, à unidade de observação e ao uso pretendido.

Para investigar diferenças salariais, por exemplo, precisamos verificar pelo menos:

  • se salário foi registrado para os trabalhadores analisados;
  • se os valores de salário são plausíveis;
  • se a codificação de sexo segue o dicionário;
  • se educação, experiência e permanência têm unidades compreendidas;
  • se cada trabalhador aparece como deveria;
  • se existem relações entre variáveis que merecem investigação.

ImportantLimpar não é apagar o que parece estranho

Uma ocorrência incomum pode ser erro, característica legítima, consequência da definição da variável ou informação importante para a investigação. Primeiro identificamos; depois investigamos; somente então decidimos.

12.3 Valores ausentes

No R, a ausência de informação é representada por NA. A função is.na() verifica cada valor e retorna TRUE quando encontra uma ausência.

is.na(head(wage1_core))
     id  wage female  educ exper tenure
1 FALSE FALSE  FALSE FALSE FALSE  FALSE
2 FALSE FALSE  FALSE FALSE FALSE  FALSE
3 FALSE FALSE  FALSE FALSE FALSE  FALSE
4 FALSE FALSE  FALSE FALSE FALSE  FALSE
5 FALSE FALSE  FALSE FALSE FALSE  FALSE
6 FALSE FALSE  FALSE FALSE FALSE  FALSE

Podemos contar o total de valores ausentes:

sum(is.na(wage1_core))
[1] 0

E contar separadamente em cada variável:

colSums(is.na(wage1_core))
    id   wage female   educ  exper tenure 
     0      0      0      0      0      0

Na versão de wage1_core utilizada aqui, nenhuma das seis variáveis possui NA. Isso é um resultado da verificação, não uma propriedade que devemos presumir para qualquer base.

12.3.1 Ausência não é zero

O valor zero é uma informação. Em tenure, ele indica que a permanência no emprego atual é inferior a um ano na forma como a variável foi registrada. Não significa que o valor esteja ausente.

sum(wage1_core$tenure == 0)
[1] 163
head(wage1_core[wage1_core$tenure == 0, ])
   id  wage female educ exper tenure
1   1  3.10      1   11     2      0
3   3  3.00      0   11     2      0
12 12  8.13      1   13     3      0
13 13  8.77      0   12    15      0
16 16 17.33      0   16    14      0
17 17  7.50      1   12    10      0

Já NA significa que não temos um valor disponível naquela célula.

Registro Significado possível
tenure = 0 valor observado e válido
tenure = NA valor ausente ou desconhecido
WarningNunca substitua NA por zero automaticamente

Trocar ausência por zero altera o significado da variável e pode modificar médias, totais, gráficos e modelos. Uma substituição só pode ser feita quando a fonte e a definição da variável justificarem essa decisão.

12.4 Criando uma cópia para aprender a diagnosticar

Como a base original não possui NA nessas variáveis nem linhas exatamente duplicadas, criaremos uma cópia de treinamento com três problemas deliberados:

  1. um salário ausente;
  2. um valor impossível de educação para esta aplicação;
  3. uma linha duplicada.
wage1_treino <- wage1_core

wage1_treino$wage[2] <- NA
wage1_treino$educ[3] <- 99
wage1_treino <- rbind(
  wage1_treino,
  wage1_treino[1, ]
)
dim(wage1_treino)
[1] 527   6
tail(wage1_treino, n = 3)
     id  wage female educ exper tenure
525 525 11.56      0   16     5      1
526 526  3.50      1   14     5      4
527   1  3.10      1   11     2      0
CautionProblemas simulados

O NA, o valor 99 e a duplicata foram introduzidos por nós somente para fins didáticos. Eles não devem ser atribuídos à base wage1 original.

Trabalhar em uma cópia preserva a fonte:

sum(is.na(wage1_core))
[1] 0

12.5 Localizando valores ausentes

Agora a verificação encontra uma ausência:

colSums(is.na(wage1_treino))
    id   wage female   educ  exper tenure 
     0      1      0      0      0      0

Para descobrir em quais linhas o salário está ausente:

which(is.na(wage1_treino$wage))
[1] 2
wage1_treino[is.na(wage1_treino$wage), ]
  id wage female educ exper tenure
2  2   NA      1   12    22      2

12.5.1 NA em cálculos

Se uma variável contém NA, a média também será NA por padrão:

mean(wage1_treino$wage)
[1] NA

O argumento na.rm = TRUE solicita que os valores ausentes sejam retirados daquele cálculo:

mean(wage1_treino$wage, na.rm = TRUE)
[1] 5.895837
Tipna.rm não limpa a base

na.rm = TRUE não apaga linhas nem modifica o objeto. Ele apenas desconsidera os NA durante a execução daquela função. A ausência continua registrada em wage1_treino.

Podemos conferir:

sum(is.na(wage1_treino$wage))
[1] 1

12.5.2 Excluir ou manter?

na.omit() produz uma base contendo apenas linhas completas:

wage1_completos <- na.omit(wage1_treino)

nrow(wage1_treino)
[1] 527
nrow(wage1_completos)
[1] 526

Isso não significa que excluir seja sempre a decisão correta. A quantidade e o motivo das ausências, as variáveis utilizadas e o objetivo da análise devem orientar a escolha.

12.6 Valores inválidos ou implausíveis

Um valor pode não estar ausente e ainda assim exigir atenção. Para esta aplicação, definiremos provisoriamente que educação deve estar entre 0 e 30 anos.

educ_invalida <- wage1_treino$educ < 0 |
  wage1_treino$educ > 30

sum(educ_invalida)
[1] 1
wage1_treino[educ_invalida, ]
  id wage female educ exper tenure
3  3    3      0   99     2      0

O valor 99 passa por is.na() porque é um número, mas viola a regra definida.

WarningOs limites precisam de justificativa

O intervalo de 0 a 30 anos é uma regra didática adequada a esta variável e a esta aplicação. Não copie o mesmo limite para outra base sem consultar o dicionário, o questionário e o contexto.

Outras verificações simples podem ser formuladas:

sum(wage1_treino$wage <= 0, na.rm = TRUE)
[1] 0
sum(!wage1_treino$female %in% c(0, 1))
[1] 0
sum(wage1_treino$exper < 0)
[1] 0
sum(wage1_treino$tenure < 0)
[1] 0

Cada expressão representa uma regra explícita. Isso é preferível a percorrer visualmente centenas de linhas procurando algo estranho.

12.7 Duplicatas

A função duplicated() identifica linhas que repetem integralmente uma linha anterior.

sum(duplicated(wage1_treino))
[1] 1
wage1_treino[duplicated(wage1_treino), ]
    id wage female educ exper tenure
527  1  3.1      1   11     2      0

Também podemos verificar especificamente se o identificador se repete:

sum(duplicated(wage1_treino$id))
[1] 1
wage1_treino[duplicated(wage1_treino$id), ]
    id wage female educ exper tenure
527  1  3.1      1   11     2      0
ImportantValores repetidos não são necessariamente duplicatas

Dois trabalhadores podem legitimamente possuir o mesmo salário, escolaridade e experiência. Uma duplicata depende da unidade de observação e das variáveis que identificam cada linha. Por isso, precisamos compreender o papel de id antes de remover qualquer registro.

12.8 Coerência entre variáveis

NoteAprofundamento

As verificações anteriores tratavam cada variável ou identificador separadamente. Agora combinaremos conhecimentos sobre duas variáveis para avaliar se a relação entre elas é coerente. Este raciocínio é importante, mas pode ser retomado depois do núcleo do capítulo.

Algumas verificações dependem da relação entre duas ou mais variáveis. Seria natural esperar que o tempo no emprego atual (tenure) não ultrapassasse a experiência total (exper).

Vamos testar essa relação na base original, sem os problemas simulados:

conflito_tempo <- wage1_core$tenure > wage1_core$exper

Encontramos 16 ocorrências. A documentação da wage1 informa que exper representa experiência potencial, não necessariamente a experiência efetivamente declarada. Ela também reconhece que alguns conflitos podem continuar sem explicação completa (Wooldridge package authors, n.d.).

CautionUma inconsistência aparente não autoriza uma correção automática

Não devemos substituir valores ou excluir as 16 linhas apenas porque tenure > exper. Primeiro precisamos compreender como cada variável foi construída e decidir se a relação afeta a análise pretendida. A ocorrência deve ser registrada e, se necessário, examinada em uma análise de sensibilidade.

Esse exemplo mostra a diferença entre três situações:

  • erro criado e conhecido: o valor educ = 99 que inserimos para treinamento;
  • duplicação conhecida: a última linha adicionada deliberadamente;
  • incoerência a investigar: casos existentes em que tenure > exper.

12.9 Tomando decisões rastreáveis

Criaremos uma nova cópia para aplicar apenas decisões justificadas sobre os problemas simulados.

wage1_limpa <- wage1_treino

O valor 99 será recodificado como ausente porque sabemos que ele foi introduzido como código inválido:

wage1_limpa$educ[
  wage1_limpa$educ < 0 | wage1_limpa$educ > 30
] <- NA

A linha integralmente duplicada será retirada porque conhecemos sua origem:

wage1_limpa <- wage1_limpa[!duplicated(wage1_limpa), ]

Não substituiremos o salário ausente por zero nem eliminaremos os casos em que tenure > exper.

dim(wage1_limpa)
[1] 526   6
colSums(is.na(wage1_limpa))
    id   wage female   educ  exper tenure 
     0      1      0      1      0      0 
sum(duplicated(wage1_limpa))
[1] 0

[1] 16

12.10 Registrando as decisões

Uma limpeza reproduzível precisa explicar o que foi encontrado e o que foi feito.

registro_qualidade <- data.frame(

    "salário ausente",
    "educação igual a 99",
    "linha integralmente duplicada",
    "permanência maior que experiência"
  ),
  origem = c(
    "simulada para aprendizagem",
    "simulada para aprendizagem",
    "simulada para aprendizagem",
    "presente na base original"
  ),
  decisao = c(
    "manter como NA",
    "recodificar como NA",
    "remover a cópia",
    "manter e documentar"
  )
)

12.11 Aprofundamento: transformando expectativas em validações

O operador %in%, apresentado no Capítulo 10, verifica se cada valor pertence ao conjunto de códigos permitidos. A função anyDuplicated() procura duplicações e retorna 0 quando não encontra nenhuma; por isso, !anyDuplicated(wage1_limpa$id) será TRUE quando todos os identificadores forem únicos.

Podemos guardar algumas verificações em um vetor lógico:

validacoes <- c(
  linhas_esperadas = nrow(wage1_limpa) == 526,
  seis_colunas = ncol(wage1_limpa) == 6,
  id_sem_repeticao = !anyDuplicated(wage1_limpa$id),
  female_binaria = all(wage1_limpa$female %in% c(0, 1)),
  salario_positivo = all(wage1_limpa$wage > 0, na.rm = TRUE),
  educacao_valida = all(
    wage1_limpa$educ >= 0 & wage1_limpa$educ <= 30,
    na.rm = TRUE
  )
)

validacoes
linhas_esperadas     seis_colunas id_sem_repeticao   female_binaria 
            TRUE             TRUE             TRUE             TRUE 
salario_positivo  educacao_valida 
            TRUE             TRUE 
all(validacoes)
[1] TRUE

Quando uma nova versão dos dados for recebida, as mesmas regras poderão ser executadas novamente.

TipVerificações são parte do código

Não deixe os critérios apenas na memória ou em anotações separadas. Transformá-los em expressões executáveis permite descobrir rapidamente quando os dados mudam ou quando uma etapa anterior produziu um resultado inesperado.

12.12 Pratique

  1. Conte quantos valores iguais a zero existem em educ, exper e tenure. Explique por que esses zeros não devem ser automaticamente transformados em NA.
  2. Crie uma regra que identifique salários superiores a 25. Verifique se ela encontra ocorrências e discuta se o limite indica erro ou apenas um valor elevado.
  3. Utilize duplicated() apenas sobre as colunas wage, female, educ, exper e tenure. Compare o resultado com a verificação que inclui id.
  4. Acrescente ao registro_qualidade uma linha descrevendo uma nova verificação.
  5. Explique por que os casos com tenure > exper foram mantidos.
  6. Execute novamente validacoes depois de alterar propositalmente um valor de female para 2.
NotePara guardar

Qualidade dos dados não é uma etapa mecânica anterior à análise. Ela exige compreender conceitos, definições e processos de coleta. Uma decisão de limpeza deve ser explícita, justificável, reproduzível e preservada no código.
