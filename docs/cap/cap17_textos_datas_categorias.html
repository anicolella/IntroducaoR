17  Textos, datas e categorias

Preparando variáveis para análise econômica

Author

Alexandre Nicolella

Published

September 15, 2026

Muitas variáveis chegam ao R como texto: nomes de estados, setores de atividade, códigos, datas e números acompanhados de símbolos. Antes de analisar esses dados, precisamos padronizar sua escrita e atribuir o tipo adequado a cada variável.

Nossa pergunta orientadora será:

Como preparar nomes de séries, áreas de aplicação, períodos e valores para produzir uma análise consistente ao longo do tempo?

NoteObjetivos do capítulo

Ao final deste capítulo, você deverá ser capaz de:

  • inspecionar o tipo de uma variável;
  • padronizar espaços, maiúsculas e minúsculas em textos;
  • localizar e substituir padrões;
  • converter números armazenados como texto;
  • criar e ordenar fatores;
  • converter textos em datas;
  • extrair ano, mês e trimestre;
  • ordenar observações cronologicamente;
  • documentar decisões de padronização.

17.1 Uma pequena base com problemas comuns

Construiremos uma tabela fictícia inspirada em séries macroeconômicas e financeiras. Ela contém inconsistências intencionais para fins didáticos.

library(tidyverse)

17.3 Removendo espaços excedentes

str_squish() remove espaços no início e no final e reduz espaços internos repetidos:

series_limpas <- series_brutas |>
  mutate(
    serie = str_squish(serie),
    area = str_squish(area)
  )

series_limpas |>
  distinct(serie, area)
# A tibble: 9 × 2
  serie    area         
  <chr>    <chr>        
1 Selic    macro        
2 SELIC    Macroeconomia
3 selic    MACRO        
4 IPCA     macro        
5 ipca     Macroeconomia
6 Ipca     MACRO        
7 Ibovespa financas     
8 IBOVESPA Finanças     
9 ibovespa FINANCAS

distinct() mostra as combinações diferentes e ajuda a verificar a padronização.

17.4 Padronizando maiúsculas e minúsculas

Podemos transformar nomes de séries em letras maiúsculas:

series_limpas <- series_limpas |>
  mutate(
    serie = str_to_upper(serie)
  )

series_limpas |>
  count(serie)
# A tibble: 3 × 2
  serie        n
  <chr>    <int>
1 IBOVESPA     3
2 IPCA         3
3 SELIC        3

Outras opções são str_to_lower() e str_to_title(). A escolha depende da convenção adotada no projeto.

17.5 Localizando e substituindo textos

A variável area utiliza diferentes nomes para os mesmos grupos. Primeiro podemos observar os valores existentes:

series_limpas |>
  count(area)
# A tibble: 6 × 2
  area              n
  <chr>         <int>
1 FINANCAS          1
2 Finanças          1
3 MACRO             2
4 Macroeconomia     2
5 financas          1
6 macro             2

Em seguida, criamos uma regra explícita de padronização:

series_limpas <- series_limpas |>
  mutate(
    area = str_to_lower(area),
    area = str_replace_all(area, "finanças", "financas"),
    area = case_when(
      area %in% c("macro", "macroeconomia") ~ "Macroeconomia",
      area == "financas" ~ "Finanças",
      .default = NA_character_
    )
  )

series_limpas |>
  count(area)
# A tibble: 2 × 2
  area              n
  <chr>         <int>
1 Finanças          3
2 Macroeconomia     6

O uso de .default = NA_character_ torna visíveis categorias não contempladas pelas regras, em vez de mantê-las silenciosamente.

ImportantPadronizar exige conhecer o significado

Duas grafias parecidas não são necessariamente equivalentes. Antes de substituir textos, consulte o dicionário e verifique casos concretos. Automatizar uma regra errada apenas torna o erro reproduzível.

17.6 Procurando padrões

str_detect() verifica se um texto contém determinado padrão. Podemos localizar séries relacionadas a preços:

series_limpas |>
  filter(str_detect(serie, "IPCA"))
# A tibble: 3 × 4
  serie area          data       valor
  <chr> <chr>         <chr>      <chr>
1 IPCA  Macroeconomia 2024-01-31 0,42%
2 IPCA  Macroeconomia 2024-02-29 0,83%
3 IPCA  Macroeconomia 2024-03-31 0,16%

Também podemos criar indicadores lógicos:

series_limpas <- series_limpas |>
  mutate(
    serie_de_precos = str_detect(serie, "IPCA")
  )

series_limpas |>
  count(serie, serie_de_precos)
# A tibble: 3 × 3
  serie    serie_de_precos     n
  <chr>    <lgl>           <int>
1 IBOVESPA FALSE               3
2 IPCA     TRUE                3
3 SELIC    FALSE               3

17.7 Convertendo números armazenados como texto

Os valores utilizam vírgula decimal e alguns incluem %. parse_number() permite informar a convenção decimal e ignora símbolos que não fazem parte do número:

series_limpas <- series_limpas |>
  mutate(
    valor_numerico = parse_number(
      valor,
      locale = locale(decimal_mark = ",")
    )
  )

series_limpas |>
  select(serie, valor, valor_numerico)
# A tibble: 9 × 3
  serie    valor  valor_numerico
  <chr>    <chr>           <dbl>
1 SELIC    11,75%          11.8 
2 SELIC    11,25%          11.2 
3 SELIC    10,75%          10.8 
4 IPCA     0,42%            0.42
5 IPCA     0,83%            0.83
6 IPCA     0,16%            0.16
7 IBOVESPA 127752      127752   
8 IBOVESPA 129020      129020   
9 IBOVESPA 127990      127990
WarningPercentual e proporção são unidades diferentes

O número 11,75% foi convertido em 11.75, mantendo a unidade percentual. Se uma fórmula exigir proporção, será necessário dividir por 100. Essa decisão não deve ser feita automaticamente sem conhecer o uso da variável.

Depois da conversão, confira valores que não puderam ser interpretados:

series_limpas |>
  filter(is.na(valor_numerico))
# A tibble: 0 × 6
# ℹ 6 variables: serie <chr>, area <chr>, data <chr>, valor <chr>,
#   serie_de_precos <lgl>, valor_numerico <dbl>

17.8 Categorias e fatores

Uma variável de texto não possui ordem definida. Um fator representa categorias e pode registrar uma ordem relevante para tabelas e gráficos.

Vamos criar uma ordem didática para as áreas:

series_limpas <- series_limpas |>
  mutate(
    area = factor(
      area,
      levels = c("Macroeconomia", "Finanças")
    )
  )

levels(series_limpas$area)
[1] "Macroeconomia" "Finanças"

Para reorganizar níveis de um fator existente, o pacote forcats oferece funções como fct_relevel():

series_limpas <- series_limpas |>
  mutate(
    area = fct_relevel(area, "Finanças")
  )

levels(series_limpas$area)
[1] "Finanças"      "Macroeconomia"

Alterar a ordem dos níveis não muda os valores das observações; muda a ordem utilizada em apresentações e análises.

17.8.1 Cuidado ao converter fatores em números

Os números internos de um fator representam posições dos níveis, não necessariamente os valores exibidos. Por isso, não use diretamente as.numeric() em um fator que contém números como rótulos.

exemplo_fator <- factor(c("10", "20", "10"))

as.numeric(exemplo_fator)
[1] 1 2 1
as.numeric(as.character(exemplo_fator))
[1] 10 20 10

17.9 Convertendo textos em datas

Datas precisam ser reconhecidas pelo R para que seja possível ordenar períodos e calcular intervalos. Como a base utiliza o padrão ano-mês-dia, empregamos ymd():

series_limpas <- series_limpas |>
  mutate(
    data = ymd(data)
  )

class(series_limpas$data)
[1] "Date"
head(series_limpas$data)
[1] "2024-01-31" "2024-02-29" "2024-03-31" "2024-01-31" "2024-02-29"
[6] "2024-03-31"

Para datas no formato dia/mês/ano, utilizaríamos dmy(). Para mês/dia/ano, mdy(). Devemos escolher a função de acordo com a convenção real dos dados.

17.10 Extraindo períodos

Depois da conversão, podemos extrair componentes da data:

series_limpas <- series_limpas |>
  mutate(
    ano = year(data),
    mes = month(data),
    trimestre = quarter(data)
  )

series_limpas |>
  select(serie, data, ano, mes, trimestre) |>
  head()
# A tibble: 6 × 5
  serie data         ano   mes trimestre
  <chr> <date>     <dbl> <dbl>     <int>
1 SELIC 2024-01-31  2024     1         1
2 SELIC 2024-02-29  2024     2         1
3 SELIC 2024-03-31  2024     3         1
4 IPCA  2024-01-31  2024     1         1
5 IPCA  2024-02-29  2024     2         1
6 IPCA  2024-03-31  2024     3         1

Também podemos representar o início do mês com floor_date():

series_limpas <- series_limpas |>
  mutate(
    mes_referencia = floor_date(data, unit = "month")
  )

series_limpas |>
  select(data, mes_referencia) |>
  distinct()
# A tibble: 3 × 2
  data       mes_referencia
  <date>     <date>        
1 2024-01-31 2024-01-01    
2 2024-02-29 2024-02-01    
3 2024-03-31 2024-03-01

Essa padronização é útil quando arquivos diferentes registram dias distintos para representar o mesmo mês.

17.11 Ordenando cronologicamente

Datas armazenadas corretamente podem ser ordenadas sem depender da ordem original do arquivo:

series_ordenadas <- series_limpas |>
  arrange(serie, data) |>
  select(serie, area, data, valor_numerico)

17.13 Registrando as decisões

Uma análise reproduzível deve documentar:

  • quais espaços e caracteres foram removidos;
  • quais grafias foram consideradas equivalentes;
  • como números e percentuais foram interpretados;
  • qual formato de data foi utilizado;
  • como categorias e sua ordem foram definidas;
  • quais valores não puderam ser convertidos.

O código registra a operação, mas comentários e texto precisam registrar sua justificativa.

17.14 Pratique

Considere a pequena tabela abaixo:

cotacoes_brutas <- tibble(
  ativo = c(" petr4 ", "PETR4", " vale3", "VALE3 "),
  data = c("15/01/2024", "15/02/2024", "15/01/2024", "15/02/2024"),
  preco = c("R$ 38,10", "R$ 42,90", "R$ 69,50", "R$ 67,20")
)

cotacoes_brutas
# A tibble: 4 × 3
  ativo     data       preco   
  <chr>     <chr>      <chr>   
1 " petr4 " 15/01/2024 R$ 38,10
2 "PETR4"   15/02/2024 R$ 42,90
3 " vale3"  15/01/2024 R$ 69,50
4 "VALE3 "  15/02/2024 R$ 67,20

Prepare uma nova tabela que:

  1. remova espaços e converta ativo para maiúsculas;
  2. converta data para o tipo data;
  3. converta preco para número utilizando vírgula decimal;
  4. ordene as observações por ativo e data;
  5. mantenha somente ativo, data e preco.
TipUma solução possível 
cotacoes_limpas <- cotacoes_brutas |>
  transmute(
    ativo = str_to_upper(str_squish(ativo)),
    data = dmy(data),
    preco = parse_number(
      preco,
      locale = locale(decimal_mark = ",")
    )
  ) |>
  arrange(ativo, data)

cotacoes_limpas
# A tibble: 4 × 3
  ativo data       preco

1 PETR4 2024-01-15  38.1
2 PETR4 2024-02-15  42.9
3 VALE3 2024-01-15  69.5
4 VALE3 2024-02-15  67.2
